## 2024-05-24 - High-Frequency Re-render Array Spreads
**Learning:** In React components subject to extremely high-frequency state updates (like `App.tsx` which handles 60fps `deviceorientation` heading updates when the AR camera is active), spreading arrays inline within the render cycle (e.g., `[...collectedLandmarks, ...localLandmarks]`) inside component props or functions creates an O(N+M) array allocation on every single frame. This triggers massive garbage collection pressure and main thread stutter, directly impacting the perceived smoothness of the AR scanner view.
**Action:** When working on components near the root of the tree or those that pass props down to rapidly updating UI nodes (like `CameraView` or `FeedSystem`), strictly verify that no new arrays or objects are dynamically allocated during the render cycle. Always consolidate and memoize lists like `[...a, ...b]` using `useMemo` at the top level before they are accessed by derived state functions or passed as props.
