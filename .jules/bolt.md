## 2024-06-25 - React.memo and DeviceOrientation API
**Learning:** High-frequency event listeners (like `deviceorientation` updating state at 60fps) in a root or high-level component (`App.tsx`) will force renders of the entire component tree and cause massive memory allocations if arrays or objects are created inline (e.g., `[...array1, ...array2]`) during render. This breaks `useMemo`/`React.memo` equality checks in child components, leading to cascading expensive renders (e.g., distance calculations in a feed, or distance cone updates in AR markers).
**Action:** Any component relying on `deviceorientation` or similar high-frequency state updates must strictly use `useMemo` for any derived object/array states, wrap callbacks passed as props in `useCallback`, and ensure all pure child components are wrapped in `React.memo()`. Avoid spread operators inside render scope unless wrapped in `useMemo`.
