## 2024-05-24 - Preserving Child Memoization Under High-Frequency Renders
**Learning:** In applications utilizing high-frequency browser APIs (like `deviceorientation` updating at 60fps), memoizing child components (e.g., `React.memo`) is completely negated if the parent component constructs arrays inline (like `[...a, ...b]`) or defines anonymous functions in JSX props (like `onDelete={(id) => ...}`). This silently breaks referential equality checks and triggers cascading, expensive re-renders in the child components, tanking performance.
**Action:** Always strictly memoize derived data arrays using `useMemo` and event handlers using `useCallback` when passing them down to memoized child components, especially in high-render-volume contexts. Furthermore, use functional state updates (`setLocalLandmarks(prev => ...)`) within those `useCallback` hooks to prevent the need for dependencies that themselves update frequently.
