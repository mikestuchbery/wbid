## 2025-02-18 - High-Frequency Renders with Callback Props
**Learning:** Component render loops tied to device orientation (e.g., `heading` state changes in AR views) fire at a very high frequency. Passing a non-memoized callback containing an array allocation (like `[...arr1, ...arr2]`) to a child component in this loop causes severe garbage collection pressure and micro-stutters, as the allocation occurs $N$ times per frame where $N$ is the number of visible items evaluated by that callback.
**Action:** Always memoize callback props (using `useCallback`) passed to high-frequency components. Inside those callbacks, strictly avoid unnecessary array or object allocations; iterate or evaluate existing state structures independently (e.g., `arr1.some() || arr2.some()`) rather than combining them into temporary variables.
