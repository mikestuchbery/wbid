## 2024-03-26 - O(N log N) GC Thrashing at 60fps
**Learning:** In a React application heavily utilizing the `deviceorientation` API (updating up to 60fps), any inline array spreads (`[...arr1, ...arr2]`) or expensive calculations (like sorting arrays or computing Haversine distances) in the render path cause severe Main Thread blocking and heavy Garbage Collection thrashing. Because `deviceorientation` forces frequent state updates on the parent component, its children re-render continuously unless strictly memoized.
**Action:** When a parent component receives high-frequency sensor updates, strictly wrap pure child components in `React.memo()`. Pre-calculate or use `useMemo` for derived states like distances, and completely avoid inline array allocations (e.g. replacing `[...arr1, ...arr2].some(fn)` with `arr1.some(fn) || arr2.some(fn)`).
