## 2025-02-28 - Optimizing High-Frequency Render Paths

**Learning:** The application heavily relies on the `deviceorientation` API, which can trigger state updates (like `heading` in `App.tsx`) up to 60fps. When parent components update frequently, passing unmemoized objects (like array spreads `[...collected, ...local]`) or inline functions to heavy child components like `FeedSystem` causes cascading re-renders and main thread blocking, even if the child's direct props seemingly haven't "changed" in value.
**Action:** Always wrap heavy child components (especially those rendering lists or complex UI) in `React.memo()`, and strictly use `useMemo` and `useCallback` with functional state updates (`setLocalLandmarks(prev => ...)`) in the parent to ensure prop referential equality is maintained across rapid render cycles. Additionally, pull O(N log N) operations (like sorting) and heavy math (like Haversine distance calculations) out of the render map loops using `useMemo` within the child component.
