## 2024-04-17 - Avoid O(N+M) allocations in deviceorientation render paths
**Learning:** High-frequency event listeners (like up to 60fps `deviceorientation`) that trigger state updates will aggressively call child components and any functions defined inline within the render body. When array spreads like `[...array1, ...array2]` are used inside utility functions that these components rely on, it creates substantial short-lived array allocations on the main thread, leading to garbage collection spikes. In React, avoiding `O(N+M)` overhead in high-frequency renders requires avoiding array spread duplication.
**Action:** Replace spread operators with separate `.some()` checks or `.filter()` chains to prevent memory allocation during validation steps. Additionally, use `useCallback` to preserve referential equality of callbacks passed to heavily re-rendered child components, preventing their re-renders.
