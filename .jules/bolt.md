## 2025-03-09 - Avoid O(N+M) allocations in render loops
**Learning:** React component states often combine local and server state arrays. In high-frequency update loops (e.g., using `requestAnimationFrame` or `deviceorientation` events like in AR Views), constructing these combined arrays directly inside render or handler closures via `[...a, ...b]` forces O(N+M) re-allocations and triggers deep equality checks or re-renders across memoized boundaries, causing GC pressure and stutter.
**Action:** Always memoize derived array combinations with `useMemo` when they serve as root dependencies for child components or frequent callbacks. Wrapping callbacks like `isLandmarkCollected` with `useCallback` using the memoized array reference further prevents prop-drilling overhead.
