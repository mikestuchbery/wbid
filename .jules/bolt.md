## 2024-03-09 - High-Frequency State Updates and Inline Array Allocations
**Learning:** The application heavily relies on the `deviceorientation` API which triggers state updates at up to 60fps when in AR scan mode. This causes rapid, continuous re-renders of `App.tsx` and its children. Inline array allocations (e.g., `[...collectedLandmarks, ...localLandmarks]`) or un-memoized callbacks within `App.tsx` were causing severe garbage collection thrashing and unnecessary `O(N)` cascading re-renders down to heavy list components like `FeedSystem`.
**Action:** When working with high-frequency state inputs (like device sensors), strictly enforce memoization boundaries. Use `useMemo` for derived arrays passed as props, ensure callbacks like delete handlers use functional state updates (`setLocalLandmarks(prev => ...)`) to maintain referential equality, and wrap pure child components in `React.memo` to shield them from the parent's sensor-driven render cycle.
