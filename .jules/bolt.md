## 2025-03-30 - Memoize derived array and complex map calculations
**Learning:** Frequent array creation (`[...collectedLandmarks, ...localLandmarks]`) inside the component body, combined with mapping complex calculations (like Haversine distances) directly within the render flow, triggers expensive O(N) allocation and O(N log N) sorting calculations on every render. Because the frontend uses the `deviceorientation` API which triggers at up to 60fps, unmemoized arrays and maps can severely block the main thread and thrash garbage collection.
**Action:** Always wrap complex arrays and calculations with `useMemo` and rely on dependency arrays to ensure recalculation only happens when data actually changes. Callbacks relying on state updates should use functional updates (`setPrev => ...`) inside `useCallback` to avoid adding changing dependencies to the callback dependency array.
